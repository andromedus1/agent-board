## Confirmed decomposition rationale

The operator confirmed candidate A (product-family split, four lanes) on
2026-10-26:

1. `mux-agent-supervisors` — multiplexer-shaped agent supervisors (Herdr's
   remote/mobile facet only, agent-deck, claude-squad, ccmux, Codirigent, and
   zellij/tmux agent managers);
2. `diy-persistent-mobile-stack` — generic always-on host persistence
   (tmux, zellij, shpool, abduco), transport (mosh, Eternal Terminal, SSH over
   Tailscale-style overlays), phone terminal clients, and the concrete
   window/tab naming, status-line, and title-passthrough mechanics;
3. `provider-native-remote` — Claude Remote Control, web and mobile sessions,
   Codex cloud and remote app-server exposure; exposed lifecycle state and
   vendor lock;
4. `mobile-first-supervisors` — phone-first agent supervisors and web-terminal
   bridges (Omnara, Happy, VibeTunnel, ttyd-class) and notification relays.

Rejected: B (layer split; products span layers and duplicate acquisition),
C (decision-option split; advocacy per option violates Scout neutrality), and
D (five lanes; the topology-fit lane would be mostly lead design reasoning over
lane 2's sources). Every lane answers a common grid — where sessions live, how
the phone connects, whether a status glyph lives in the session name and
survives rename, native versus screen-inferred status and its visibility, and
known failure modes — so the parent compares along dimensions rather than
ranking products. Topology fit with Agent Board's Ghostty title contract is
assessed in the parent from lane 2's mechanics and is marked as composed
judgment. Known risk: lane 4 sources are fast-moving and marketing-heavy.

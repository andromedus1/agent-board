## Confirmed decomposition rationale

Operator confirmed candidate A (component split) on 2026-11-10, with the
instruction to de-emphasize the Agent Board comparison because building a
replacement for Herdr is not under consideration:

1. `herdr-ecosystem` — Herdr TUI vs Desktop, macOS server, remote attach,
   labels/rename, status detection, notification hooks, wherdr, Herdr Projects,
   open remote defects, remote security; currency check of agent-deck and ccmux.
2. `android-access` — Moshi Android vs iOS parity, moshi-hook, mosh over
   Tailscale, approval semantics; alternatives (Termux, JuiceSSH, web/PWA
   supervisors, provider-native remote).
3. `mac-mini-headless-host` — FileVault on Apple silicon and macOS 26 headless
   reboot, Tailscale variants and pre-login start, SSH, power recovery, account
   separation.
4. Agent Board salvage — lead-inline, light: which existing pieces, if any, are
   worth keeping alongside Herdr.

Rejected: B (criteria split; duplicate acquisition), C (per-stack advocacy;
triplicates host and Android work), D (separate Model B lane; operator sequences
orchestration last). Common grid for every lane: where sessions live, device
connection, label visibility per device, native vs inferred status, approval
carriage, notifications, disconnect vs reboot survival, known defects, security.

Self-flags: Herdr alternatives get a currency check only; Model B depth is
light; thinly documented products are confidence-marked.
